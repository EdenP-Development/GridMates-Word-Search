## Context / audited source

The v80 Font and Portrait visual work passed code QA, with screenshots looking much better. The next unreviewed section is **Records**, accessible from Profile → Records & statistics. This was a source-backed UX audit rather than claiming the owner had supplied Records screenshots.

Inspected `app/src/main/java/com/playereden/gridmates/wordsearch/SoloRecordsScreen.kt`, its Android UI navigation test, older WS07F acceptance/92-test emulator evidence, and core Race/Duel journal rules. Found two concrete UI risks:

1. The shell already prints `Records`, but the screen added a decorative `Your puzzle journal` heading and a `Browse your results` section heading above the Solo/Race/Duel tabs. This delays navigation on phones and repeats hierarchy.
2. Race/Duel winner and partner score, and Solo theme/difficulty and hint classification, sat side-by-side in a `Row(Arrangement.SpaceBetween)`; long numbers, font scaling and translations can crowd/clash. Race/Duel metrics were always two columns, even at enlarged system text, unlike the adaptive Solo metric cards.

**Important existing design confirmed:** Only the active Solo/Race/Duel journal is rendered; Solo/Daily summary is only on Solo; `rememberSaveable` keeps independent tab/page positions; results are paged four at a time with no UI truncation, and the local Race/Duel journal rules deduplicate validated host results. No changes necessary to underlying privacy/data semantics or journal calculations.

## Owner v81 handset screenshots — visual assessment

**Evidence:** Five owner-supplied Android v81 screenshots in design chat on November 14, 2026 (not stored in GitHub): Player Profile with Explore, Records Solo, Records Race, Records Duel, and My Puzzles. These are direct device visual evidence only, **not** tapping/persistence/instrumentation proof.

### Screen observations
- **Profile:** Explore heading, separate puzzle/word totals, portrait and native cream/gold navigation appear visually coherent and readable. Preserve.
- **Solo Records:** concise Records header and tabs visible near the top; adaptive layout shows **Completed + Words found** in two columns and **With hints** full width. Daily Journal and Recent puzzles empty state have matching ornate frames. No obvious overlap. The 0-completion/0-result state is consistent with the test profile as displayed, but game-save/reward correctness is not established by the screenshot. Preserve current Solo treatment.
- **Race and Duel:** both display four vertically stacked, full-width metric frames; the empty-result panels appear only at or below the bottom of the viewport. At the photographed size, metric labels/values are short and **2×2 cards would fit** and improve scanning. Source cause verified: `MatchSummaryMetrics` uses `if (maxWidth < 350.dp || largeText)`, while the shell's normal horizontal padding reduces actual content width below 350dp even on an ordinary phone. Unlike Solo's 2+1 approach, this forces an overly aggressive **four-card single-column** fallback. This is a density/usability issue, not a records data defect. Recommend a compact 2×2 normal-phone arrangement with vertical stacking only when actual card width cannot safely hold labels and values or fontScale is significantly enlarged; consider 2×2 for ordinary large-font scenarios only when still legible. Preserve metric values and local Race/Duel separation.
- **My Puzzles:** shows clear Currently Playing Woodland 15×15 Classic, 0/16 words and time, Continue current puzzle, New Solo and Paused 0/24 empty state. Functional affordances look sensible; its plain white card is not using the framed cream/gold family adopted elsewhere. Treat future shared-panel reuse as **lower priority**, without touching save/reopen/slot semantics. No claim that saved progress actually persisted after relaunch.
- **Visual QA outcome:** Profile and empty-state Solo Records are provisionally acceptable from screenshots; Race/Duel metric density needs the next small focused adjustment. Do **not** rework the approved Library, Portraits, Fonts, Achievements, or puzzle views just to add detail.
- **Still unverified:** populated Solo/Race/Duel results (including score/date wrapping), Previous/Next pagination with 5+ matches, all three real navigations on smaller screens/200% text/TalkBack, actual save → resume → complete → reward → Records round-trip, two-phone Race/Duel, font License and equip persistence.
- **Proposed next pass WS16BX:** change only `MatchSummaryMetrics` responsive threshold / arrangement, add source and 320–360dp instrumentation coverage, repeat both Android and independent art builds; capture Race/Duel after screenshot review. Later tackle My Puzzles card re-use only if desired. Keep PR #131 DRAFT.
